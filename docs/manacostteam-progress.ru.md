# Переход к ManacostTeam: поэтапный план

Этот документ — рабочая карта постепенного перехода от интерфейса и терминов OpenBot к
ManacostTeam. Каждый этап должен быть отдельным небольшим выпуском с проверяемым результатом;
следующий этап не маскирует незавершённость предыдущего.

## Принцип перехода

Сначала меняется то, что видит команда, затем стабилизируются контракты и только после этого
переименовываются внутренние сервисы и deployment-имена. Совместимость с существующими каналами,
агентами, OAuth и сохранёнными данными сохраняется до отдельного миграционного окна.

## Этапы и критерии готовности

| Этап | Что делаем | Критерий выхода | Состояние |
| --- | --- | --- | --- |
| 0. Baseline | Фиксируем health, smoke, runtime-профиль и security gate | Есть воспроизводимый отчёт и точка отката | Выполнен |
| 1. Скорость | Выносим Copilot runtime из общего auth-shell; ограничиваем окно длинной истории | Нагрузка на чат не попадает на страницы без чата; baseline browser gate PASS | Выполнен |
| 2. Оболочка | Главная, быстрые действия, недавние диалоги, единая навигация и русские labels | Пользователь начинает задачу с главной за один клик; мобильная версия не теряет действия | Выполнен |
| 3. Выполнение | Разделяем логический запрос и протокольные runs; вводим статусы, reconnect и строгий результат | Прогресс не называется ответом; research/YouTube не завершаются без валидного Markdown-файла | Выполнен |
| 4. Результаты | Восстанавливаем файлы из истории и готовим единый центр результатов | Потерянный AG-UI envelope не скрывает файл; Markdown и другие результаты находятся из одного места | Выполнен |
| 5. Настройки и интеграции | Профиль, подключения, команда и параметры ИИ с безопасными состояниями | Для каждого изменения видны состояние, ошибка и способ повторить; секреты не возвращаются в UI | В работе |
| 6. Внутреннее имя | Переводим сервисные labels, метрики и deployment после миграции данных | Старые ссылки работают через compatibility alias; есть rollback без потери данных | Финальный |

## Что проверяем на каждом выпуске

- продуктовый smoke в production и health всех контейнеров;
- типы, форматирование, целевые тесты и `git diff --check`;
- security-проверка без вывода секретов;
- runtime p50/p95 для desktop и mobile;
- понятный rollback: предыдущий image tag и обратимый database/API change;
- короткая запись в changelog и обновление соответствующего runbook.

## Текущая точка

Главная ManacostTeam уже показывает быстрые действия, три последних диалога и карточки
сотрудников. Навигация настроек переведена на единые названия «Основные», «Интеграции» и
«Галерея компонентов». Последний полный browser gate (Chromium, desktop 1440×900 и mobile
390×844 с 4× CPU slowdown) зафиксирован на ревизии `93cc34b`; все сценарии PASS: desktop p95 не
превысил 45 мс, mobile p95 — 153 мс. Подробные числа находятся в
[`runtime-performance-evidence.ru.md`](runtime-performance-evidence.ru.md).

На ревизии `8008525` продакшен уже получил два важных исправления: история чата повторно находит
созданный агентом файл через авторизованный список вложений, а естественные сообщения вроде
«продолжаю проверку» остаются незавершённым прогрессом. Это закрывает случаи, когда YouTube или
Главный Аналитик фактически создали результат, но интерфейс показывал только текст.

На ревизиях `c175fac`–`93cc34b` добавлен read-only центр результатов: серверная пагинация по
активным каналам, поиск по имени и типу файла, preview/download с повторной авторизацией каждого
объекта. Ревизия `4f80161` опубликована в `main` и выкачена в production; smoke-проверка вернула
`/health=200`, закрытый `/api/results=401`, все runtime-контейнеры остались `healthy`. Следующий
вертикальный срез — настройки и диагностика подключений: сначала состояния и
безопасные ошибки, затем изменения профиля/команды. Новые разделы не должны дублировать OAuth- или
role-логику; они используют существующие серверные контракты.

## Порядок ближайших выпусков

1. Настройки и интеграции: оформить ChatGPT/OpenRouter, Google Drive/Docs и Telegram как отдельные
   проверяемые подключения с revoke/rotate и без возврата секретов.
2. UX статусов: один timeline логического запроса (`принят → выполняется → сохраняется → готово`),
   понятная кнопка повтора и видимый blocker вместо ложного «Ответ готов».
3. Переименование: только после двух стабильных выпусков перевести внутренние labels и имена
   контейнеров, сохранив compatibility alias и быстрый rollback.

Каждый пункт выпускается отдельным небольшим PR/коммитом: targeted tests → typecheck/build →
security-check → production health/smoke → запись результата в этот документ.

## Не делаем преждевременно

- не переименовываем production-контейнеры до проверки миграции и rollback;
- не добавляем переключатели для ещё не реализованных возможностей;
- не считаем «ответ готов» завершением задачи, если heartbeat или обязательный artifact ещё не
  подтверждены;
- не переносим credential values в Git, документацию, логи или клиентский bundle.
