# Переход к ManacostTeam: поэтапный план

Этот документ — рабочая карта постепенного перехода от интерфейса и терминов OpenBot к
ManacostTeam. Каждый этап должен быть отдельным небольшим выпуском с проверяемым результатом;
следующий этап не маскирует незавершённость предыдущего.

## Принцип перехода

Сначала меняется то, что видит команда, затем стабилизируются контракты и только после этого
переименовываются внутренние сервисы и deployment-имена. Совместимость с существующими каналами,
агентами, OAuth и сохранёнными данными сохраняется до отдельного миграционного окна.

## Этапы и критерии готовности

| Этап | Что делаем | Критерий выхода | Состояние |
| --- | --- | --- | --- |
| 0. Baseline | Фиксируем health, smoke, runtime-профиль и security gate | Есть воспроизводимый отчёт и точка отката | Выполнен |
| 1. Скорость | Выносим Copilot runtime из общего auth-shell; проверяем длинную историю | Нагрузка на чат не попадает на страницы без чата; все 16 browser-сценариев PASS | Выполнен |
| 2. Оболочка | Главная, быстрые действия, недавние диалоги, единая навигация | Пользователь начинает задачу с главной за один клик; мобильная версия не теряет действия | Выполнен частично: главная и настройки |
| 3. Настройки | Разделяем профиль, подключения, команду и параметры ИИ; показываем понятные состояния | Для каждого изменения видны состояние, ошибка и способ повторить; секреты не возвращаются в UI | Следующий |
| 4. Выполнение | Единая модель статусов задачи, heartbeat, остановки и передачи сотруднику | `queued → running → waiting → succeeded/failed/cancelled` согласованы между UI, API и realtime | Следующий |
| 5. Результаты | Единый центр файлов и результатов с фильтрами по задаче и сотруднику | Markdown, Google Docs и другие результаты находятся из одного места и имеют понятный статус | Следующий |
| 6. Внутреннее имя | Переводим сервисные labels, метрики и deployment после миграции данных | Старые ссылки работают через compatibility alias; есть rollback без потери данных | Финальный |

## Что проверяем на каждом выпуске

- продуктовый smoke в production и health всех контейнеров;
- типы, форматирование, целевые тесты и `git diff --check`;
- security-проверка без вывода секретов;
- runtime p50/p95 для desktop и mobile;
- понятный rollback: предыдущий image tag и обратимый database/API change;
- короткая запись в changelog и обновление соответствующего runbook.

## Текущая точка

Главная ManacostTeam уже показывает быстрые действия, три последних диалога и карточки
сотрудников. Навигация настроек переведена на единые названия «Основные», «Интеграции» и
«Галерея компонентов». Последний browser gate (Chromium, desktop 1440×900 и mobile 390×844 с
4× CPU slowdown) прошёл на ревизии `4d71f7e`; подробные числа находятся в
[`runtime-performance-evidence.ru.md`](runtime-performance-evidence.ru.md).

Следующий вертикальный срез — настройки и диагностика подключений: сначала read-only состояния и
безопасные ошибки, затем изменения профиля/команды. Новые разделы не должны дублировать OAuth- или
role-логику; они используют существующие серверные контракты.

## Не делаем преждевременно

- не переименовываем production-контейнеры до проверки миграции и rollback;
- не добавляем переключатели для ещё не реализованных возможностей;
- не считаем «ответ готов» завершением задачи, если heartbeat или обязательный artifact ещё не
  подтверждены;
- не переносим credential values в Git, документацию, логи или клиентский bundle.
