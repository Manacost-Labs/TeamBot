# Skills и автономные запуски ManacostTeam

ManacostTeam подключает канонические skills сервера через отдельный, проверяемый контур. Skill — это
инструкция; он не выдаёт Bot новых прав. Перед запуском сервер проверяет, что skill выдан этому Bot,
а каждый заявленный инструмент пересекается с уже выданными MCP-грантами.

## Канонический каталог

Источник задаётся только серверной переменной `MANACOST_CANONICAL_SKILL_MANIFESTS`. В запросе нельзя
выбрать путь, репозиторий или commit. Каждый allowlisted root должен содержать `manifest.json` со
схемой:

```json
{
  "schemaVersion": 1,
  "repo": "https://github.com/Manacost-Labs/skills",
  "commit": "<полный 40- или 64-символьный commit>",
  "skills": [
    {
      "id": "data/audit-parser-system",
      "title": "Parser audit",
      "summary": "Проверка парсеров",
      "path": "skills/data/audit-parser-system/SKILL.md",
      "sha256": "<sha256 файла SKILL.md>",
      "tools": ["parser-ops/audit_all_sources"]
    }
  ]
}
```

Для каждого skill и companion-файла проверяются относительный путь, отсутствие symlink-выхода,
размер (до 512 KiB) и SHA-256. Идентификаторы сохраняют namespace (`data/...`, `core/...`).
Импорт выполняется при старте, если переменная задана, и вручную администратором через
`POST /api/manacost-team/catalogue/sync`.

Пример переменной (значения нужно получить из подготовленного read-only bundle):

```sh
MANACOST_CANONICAL_SKILL_MANIFESTS='[{"id":"server-skills","root":"/var/lib/openbot/canonical-skills","repo":"https://github.com/Manacost-Labs/skills","commit":"<commit>","manifestSha256":"<sha256 manifest.json>"}]'
```

Не указывайте рабочее дерево с незакоммиченными изменениями. Сначала соберите bundle из нужного
commit, сгенерируйте манифест и подключите его read-only. Публичный endpoint каталога возвращает
только названия, описания и provenance; исходный текст выдаётся отдельному Bot только после проверки
его grant.

## Управление автономностью

`POST /api/manacost-team/runs` принимает `agentId`, `skillSlug`, действие и небольшой JSON-ввод.
Запуск сразу сохраняется в PostgreSQL и отвечает `202` с `run.id`; дальнейшая работа продолжается на
сервере, поэтому закрытие браузера её не отменяет. `GET /api/manacost-team/runs/:id` возвращает статус
и чекпоинты. Если процесс был перезапущен до завершения, сначала проверь последний чекпоинт, затем
владелец или администратор может вызвать `POST /api/manacost-team/runs/:id/resume`. Исполнитель
Parser Ops должен быть идемпотентным: при сбое после внешнего действия восстановление может повторить
его, поэтому перед `resume` нужно сверить состояние источника или рабочей копии.

Автоматические действия Parser Ops:

- `audit` — полный аудит источников;
- `diagnose` — диагностика одного источника;
- `retry` — ограниченное обновление известных источников;
- `codegraph` — исследование связей кода;
- `validate` — проверка изолированного workspace.

`publish` и `deploy` никогда не запускаются автоматически. Для них сервер выдаёт короткоживущий
одноразовый `approvalToken`; публикация возможна только через администраторский endpoint
`POST /api/manacost-team/runs/:id/approve`. Токен хранится только в виде хэша, проверяется по сроку и
атомарно помечается использованным.

Профиль по умолчанию ограничивает запуск 12 шагами, 20 минутами, двумя retry и 20 000 символами
результата. Администратор может изменить только числовые лимиты через `PUT /api/manacost-team/profile`;
набор автоматических действий является частью серверного кода и не расширяется из пользовательского
запроса.

## Безопасность и наблюдаемость

- actor и Bot берутся из сессии и серверной проверки доступа, а не из текста модели;
- аргументы ограничены по размеру/глубине и не принимают поля, похожие на credentials;
- каждый переход статуса записывается в append-only checkpoints;
- ошибки ограничены и очищаются от Bearer/token-подобных значений;
- `publish`/`deploy` остаются approval-only, даже если skill объявляет соответствующий инструмент;
- реальные вызовы Parser Ops проходят существующий MCP grant, action policy и audit trail.

Полный список ручек доступен после авторизации на префиксе `/api/manacost-team`.
