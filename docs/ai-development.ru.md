# Разработка ManacostTeam с помощью ИИ

Этот документ — короткий контракт для человека и AI-агента, который меняет проект. Его цель —
сократить количество догадок: сначала определяется владелец поведения, затем меняется минимальный
слой и проверяется его контракт.

## Карта проекта

| Слой | Где искать | Что здесь должно жить | Чего здесь не должно быть |
| --- | --- | --- | --- |
| Web-композиция | `app/src/routes/` | layout, loader страницы и связь модулей | прямые `fetch`, бизнес-правила и секреты |
| Переиспользуемый UI | `app/src/components/` | визуальные компоненты, состояния загрузки и ошибки | авторизация и собственные варианты API-транспорта |
| Клиентские домены | `app/src/lib/<domain>/` | типы, query/mutation, чистые reducer-ы и доменные API | чтение `.env`, серверные права и дублирование транспорта |
| Общий транспорт | `app/src/lib/client.ts` | credentials, JSON-конверт, отмена и короткие deadlines | знание смысла конкретного домена |
| API-домены | `server/src/<domain>/` | маршруты, валидация, авторизация, БД и интеграции | доверие к данным из браузера |
| Долгие задачи | `worker/src/`, `server/src/work/` | очередь, lease, retry и фоновые sweep-ы | таймеры, являющиеся единственным источником истины |
| AG-UI и агенты | `agent-*` | протокол запуска, инструменты и изоляция процесса | обход server gateway или выдача чужих credentials |
| Контракты | `shared/` | типы и маркеры, которые обязаны совпадать между процессами | UI-детали и runtime-состояние конкретного экрана |

Для конкретной задачи сначала найдите домен, который владеет фактом. Например, статус запуска
живёт в `app/src/lib/copilot/run-state.ts`, а не в заголовке страницы; разрешение действия живёт
на сервере, а не в переключателе интерфейса; артефакт считается созданным только после ответа
серверного хранилища.

## Инварианты, которые нельзя ломать

1. Каждый обычный JSON-запрос проходит через `app/src/lib/client.ts`. Прямой `fetch` допустим для
   multipart, download или streaming только с комментарием о причине.
2. Браузер не решает права. Сервер делает `resolve → policy → audit → action/refusal`; проверка в
   UI является только удобством и не является защитой.
3. Терминальный статус запуска монотонен. Позднее событие старого поколения не может вернуть новый
   запуск в `working`; progress-note не является финальным ответом.
4. История и артефакты проверяются по серверному источнику. Кэш и `sessionStorage` ускоряют экран,
   но не становятся авторитетом.
5. Вывод модели, пользовательский текст и содержимое файлов не попадают в логи диагностики.
   Идентификаторы, тип ошибки и длительность допустимы; секреты — нет.
6. Изменения делаются в source-репозитории `/srv/projects/...`. `/var/www` и release-копии меняются
   только отдельной операцией deployment.
7. Короткий запрос должен иметь deadline или отмену. Долгая работа должна иметь явный lifecycle,
   а не произвольный таймер, который объявляет её завершённой.

## Безопасный цикл изменения

1. **Сформулировать факт.** Записать, что видит пользователь, какой серверный факт является
   источником истины и что считается успешным результатом.
2. **Построить impact map.** Найти route → component → domain client → server route → worker/agent.
   Если слой не меняется, не добавлять туда копию логики.
3. **Сделать один вертикальный срез.** Сначала контракт и чистая функция, затем сервер/клиент и UI.
   Новую абстракцию добавлять только если у неё есть два реальных потребителя.
4. **Добавить проверку рядом с изменением.** Для reducer-а — таблица переходов, для API — нормальный,
   ошибочный и отменённый запрос, для UI — ошибка/повтор и доступность клавиатурой.
5. **Проверить проект.** Минимум: `bun run format:check`, `bun run lint`, `bun run typecheck`,
   затронутый тест и `bun run build`. Перед release дополнительно запускаются полный `bun run test`
   и smoke/performance-проверки по области изменения.
6. **Зафиксировать срез.** Один смысловой commit с коротким сообщением. Не смешивать рефакторинг,
   миграцию и deployment; rollback должен быть понятен по одному commit.

### Шаблон задания для AI-агента

```text
Контекст: какой пользовательский сценарий сейчас нарушен.
Цель: наблюдаемое поведение после изменения.
В scope: конкретные домены и файлы.
Не в scope: соседние улучшения, которые не нужны для цели.
Инварианты: авторизация, источник истины, таймауты, секреты, совместимость.
Проверки: тесты, typecheck, lint, build и при необходимости smoke/performance.
Результат: изменённые файлы, проверки и оставшиеся ограничения.
```

## Что уже укреплено в runtime

- `RuntimeErrorBoundary` в корне приложения изолирует неожиданный render failure, даёт повторить
  попытку и показывает безопасный incident code без текста исключения.
- TanStack Router игнорирует `*.test.*` и `*.spec.*`, поэтому тест рядом с route не становится
  страницей при следующей генерации карты маршрутов.
- Общий client transport поддерживает `ClientTimeoutError` и deadline для коротких запросов.
  Управление компьютером ограничено 10 секундами и при недоступности сервиса завершается fail-closed;
  долгие AG-UI runs этот лимит не получают.

## Варианты desktop для macOS и Windows

UI уже отделён от server API, поэтому desktop лучше строить как оболочку вокруг того же приложения,
а не переписывать доменную логику дважды.

| Вариант | Плюсы | Ограничения | Роль в проекте |
| --- | --- | --- | --- |
| PWA | почти нулевая стоимость, один build и быстрый rollout | всё ещё зависит от браузерного окна и его политики | промежуточный installable web-клиент |
| **Tauri 2** | маленький пакет, нативное окно, WebView2 на Windows и WKWebView на macOS, системный keychain | нужно поддерживать Rust-команды и различия webview | рекомендуемый основной desktop-shell |
| Electron | одинаковый Chromium, проще перенести сценарии, завязанные на Chromium/Playwright | большой размер и расход памяти, более широкая поверхность обновлений | запасной вариант при требовании полного Chromium |

Рекомендуемый порядок:

1. Сначала завершить web-стабильность и вынести все платформенные зависимости за `client`, auth и
   artifact seams. Desktop не должен получать `.env`, host profile или общий API key.
2. Собрать Tauri proof-of-concept с удалённым ManacostTeam API, Telegram/Better Auth в системном
   окне и хранением локальных refresh-данных только в OS keychain. Server остаётся источником прав,
   каналов и запусков.
3. Добавить deep links, безопасное открытие внешних ссылок, offline/read-only экран и автообновление;
   отдельно подписать bundles для Apple и Windows. Live computer продолжает работать на сервере,
   поэтому desktop не получает доступ к Docker или production workspace.
4. Если проверка показывает, что встроенный WebView ломает нужный сценарий, повторить тот же shell на
   Electron. Это смена упаковки, а не переписывание доменных модулей.

Desktop-реализация начинается отдельной задачей после стабилизации web-пути; текущий документ фиксирует
решение и границы, но не добавляет тяжёлую зависимость в production build.
